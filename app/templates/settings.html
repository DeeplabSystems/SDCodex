System & Update

Pull the latest core code and rebuild/restart the container by running update.sh. Because the app runs inside Docker, the actual git pull + docker compose up -d --build runs on the host: this button records an update request, and a small host-side watcher (scripts/ui-update-watcher.sh, typically on cron) applies it.

Self-update in the UI

Replaces this running container entirely from here, without a host-side watcher or cron: the app talks to the Docker Engine over the mounted socket, pulls the new image, pre-creates a replacement container, and launches a tiny updater sidecar that swaps them (stop → rename → start). Requires read-write access to the host Docker socket.

Cron setup (apply from here)

Choose how often the host should check for updates. This writes your choice to the shared state file; the host-side agent (scripts/ui-cron-agent.sh) installs it into your host crontab. Start the agent once on the host (runs in a terminal): 

/path/to/SDCodex/scripts/ui-cron-agent.sh --watch

Host watcher — set this up once

The web app cannot run Docker itself (no Docker install inside the container). You must run the watcher on the host, e.g. via cron:

# every 5 minutes, as the user that owns the repo + Docker
*/5 * * * * /path/to/SDCodex/scripts/ui-update-watcher.sh --once

Or run it continuously in a terminal:

/path/to/SDCodex/scripts/ui-update-watcher.sh --watch
